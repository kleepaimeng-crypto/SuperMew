# 项目对话检索优先修复（2026-11-18）

用户在项目对话问“Java异常处理有哪些？”时模型直接回答，追加“核对下知识库”才检索。用户明确授权修复。本包沿现有自动工具选择实现项目优先规则，不增加独立意图路由模型、额外调用额度或强制所有请求检索。

## 原因与修复范围

此前普通对话与项目对话共用“普通概念解释可以直接回答”的规则。项目隔离只在工具真正执行后，根据Thread选择知识库；首次模型请求没有明确的项目模式与文档目录。因此，“Java异常处理有哪些？”可以被当成普通概念问题跳过工具。

本包区分两种规则：

- 普通对话保持原自动规则，普通概念解释可以直接回答。
- 项目对话默认将与项目有关或不确定是否有关的事实、概念、操作方法问题视为需要项目资料的问答，先调用可用的`knowledge_search`；不能要求用户额外说“核对知识库”。闲聊、纯改写、解释上条且不新增事实、明显无关的问题可以直接回答。
- 没有可用工具时说明限制，目录不等于已经检索。继续使用`tool_choice=auto`；规则改善模型选择，不能保证所有措辞和模型都百分之百遵守。

## 代码职责和数据流

```text
Run → 已校验归属的Thread → Project名称
                           ↓
         当前用户 + 当前项目 + 已发布且未下线文档的有限目录
                           ↓
        ProviderRequest.project_context（只用于路由提示）
                           ↓
  首轮 / 工具反馈 / HITL恢复 / 私有格式修复中的系统指令
                           ↓
  模型自动选工具 → 原Registry/Guardrail → 原项目检索范围
                           ↓
       原Evidence与答案校验 → 原Message/Run终态事务
```

| 模块 | 作用 |
| --- | --- |
| [execution/project_context.py](../src/minimew/execution/project_context.py) | 不可变ProjectContext及目录读取。按用户和Thread查项目；只取本用户、本项目、当前已发布且未下线文档的标题。最多8项，每项80字符，名称最多100字符；序列化目录最多1000字符，省略时标记`catalog_limited`。 |
| [execution/repository.py](../src/minimew/execution/repository.py) | 在原请求构建事务中取得项目上下文，普通Thread返回None；项目识别不依赖是否有手工记忆。 |
| [execution/provider.py](../src/minimew/execution/provider.py) | 内部请求DTO显式携带项目上下文；评测Case请求不允许冒充项目聊天。不是公开API字段。 |
| [execution/prompts.py](../src/minimew/execution/prompts.py) | 基础规则 + 普通/项目策略 + 有界目录数据 + 当前Run实际检索状态。目录内容按不可信数据处理，不得作为指令或Evidence。 |
| [execution/service.py](../src/minimew/execution/service.py) | 首轮、工具反馈和预算收尾均传递同一请求的项目上下文；HITL恢复仍恢复原Run/工具/证据，不重跑已完成工具。 |
| [execution/grounded.py](../src/minimew/execution/grounded.py) | 私有格式修复也携带项目模式和实际检索状态，不放宽来源校验或允许执行工具。 |

项目当前只有名称，没有说明字段；本次未新增项目说明或数据库列。目录是请求构建时的提示投影，可以随发布/下线变化，不能用于证明文档正文或替代工具首次调用时冻结的检索scope。实际权限、来源版本和HITL证据仍由原正式链路拥有。原始历史消息、项目记忆快照与文档索引不重写。
