# 内部评判响应与错误透传修复（2026-11-19，BUG-007）

用户授权“建议并修复”。本包修复内部模型响应不稳定和错误被泛化两条链路，保持原Run、检索scope、Evidence、HITL与终态事务，不增加模型调用总额度，不重跑旧失败任务。

## 已确认的问题

原任务`2755d684-7a74-48cc-b67e-db0d093354c2`的Journal显示：首次检索保留6项材料，正常评判为insufficient，拆解为4个子问题且均完成检索/评判；第87条汇总评判事件以`PROVIDER_INVALID_RESPONSE`失败，第88条tool.failed和第90条run.failed被外层包装为`TOOL_EXECUTION_FAILED`。

材料不足是合法Grade；只有健康ambiguous且需要补充条件时进入HITL。响应异常尚未产生合法Grade，不能被解释成资料不足或用户需要澄清。原始无效响应未保存在公开事件里，现有证据无法追溯具体哪个字段错误；本包不伪称已查明旧响应内容、不补造历史日志。

## 实现与职责

```text
新Run/Case冻结 reasoning.structured_output=json-repair-v1
  → ModelCaller：同一问题/材料 + JSON协议
  → DeepSeekProvider：沿原SDK流发送response_format=json_object
  → JSON解析 → Pydantic字段校验 → Grade引用/充分性一致性校验
  → 无效时至多一次重新评判，仍使用原输入和原预算
  → 合法Grade进入原RAG路由；再次失败抛原ProviderFailure
  → 原tool.failed与Run失败事务持久化同一错误码
  → SSE/历史重放显示真实阶段和错误说明
```

一次结构修复也占原额度；没有修复额度或上下文装不下时记录跳过原因，不能通过FinalizationReserved把已发生的模型故障变成insufficient。真正耗尽预算时仍按原预算错误结束，并在诊断cause_code中保留先前校验原因。plan/rewrite原有实体锚点等业务校验仍保留，不通过删字段、改原文或随意补引用修复。

JSON模式约束语法，字段和事实一致性仍由程序校验。参考[DeepSeek JSON Output官方说明](https://api-docs.deepseek.com/guides/json_mode/)。

## 日志与部署

默认日志目录为MiniMew工作目录的`.artifacts/logs`，可通过`MINIMEW_DIAGNOSTIC_LOG_DIR`修改。每个进程写`execution-<pid>.jsonl`，单文件5MiB、保留3份轮转备份；关闭服务移除并关闭自己的handler。时间使用UTC，可按Run ID跨文件查询：

```powershell
Get-ChildItem .artifacts/logs/execution-*.jsonl* | Select-String -SimpleMatch '目标Run UUID'
```

修改从API/运行中的Evaluation Worker重启后生效；新建工作才冻结新策略。旧Run和旧Case不改写快照、不自动重试，原失败记录保留。此次未重启用户服务、未迁移开发库或重建索引。

没有新增ErrorCode或Event schema、数据库DDL、依赖、评分语义或baseline。`ReasoningPolicy`增加可选标记，因此从正式生成器同步了OpenAPI/TS与`job-request-v2` JSON Schema；旧空标记不进入序列化，旧快照摘要保持。
