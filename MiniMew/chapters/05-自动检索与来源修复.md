# 自动工具选择与回答来源修复（2026-11-18）

本记录是第五章 Agent/引用链路的缺陷修复，不新增教学阶段。用户已明确授权“先实施前五项”：统一首轮规则、注入当前检索状态、处理历史引用、条件化回答格式、校验所有答案出口。独立意图路由器、真实模型准确率实验和第九章功能不在本包。

## 问题与原因

旧 Thread 中，模型可能直接沿用历史助手文字里的“已检索”和 `[E1]`。普通新 Run 的请求原先没有系统规则，只有工具成功执行后才注入混合回答协议；未执行知识工具的最终文本直接返回，没有经过引用验证。因此没有 Tool Event、没有本 Run Evidence 的回答仍可能包含文档分区和裸引用。

这不能解释成检索排序失败：没有调用检索，就不能据此评价召回质量。历史上下文是影响因素，无法从日志证明模型内部究竟如何推理。

## 当前职责与调用关系

```text
ExecutionRepository.request
  → context.build_messages：完整历史问答的有界投影
  → RunExecutor：原Registry绑定工具、原Run预算与期限
  → prompts.chat_instructions：基础规则 + 当前证据目录状态 + 条件回答格式
  → DeepSeekProvider：SystemMessage + 历史/问题/工具结果，仍为tool_choice=auto
  → 工具调用：原Registry / Guardrail / KnowledgeService
  → tool.started / tool.completed 或 tool.failed，沿原Journal/SSE显示
  → 更新同一Run的系统指令，再次调用模型
  → direct_answer或grounded_answer校验
  → 原finish事务保存Message与权威Run终态
```

- [prompts.py](../src/minimew/execution/prompts.py)：基础规则、可见工具名、`not_searched / searched_with_evidence / searched_without_evidence`、本 Run 可用引用编号与条件格式。状态直接读取现有 Run 私有 EvidenceDirectory，不增加数据库或内存镜像事实来源。
- [context.py](../src/minimew/execution/context.py)：模型输入中的历史助手文字加历史标识，移除旧 `[E<n>]` 并转换旧分区标题，保留正文语义；投影后再计入上下文预算。用户当前问题、数据库原消息、历史引用展示不变。
- [service.py](../src/minimew/execution/service.py)：首轮和工具结果后组装规则；HITL恢复根据已恢复证据目录重建当前状态；预算收尾仍禁用工具，未提高请求次数或期限。
- [grounded.py](../src/minimew/execution/grounded.py)：未检索时拒绝保留的文档引用标记及文档依据标题，记录`answer_validation / citation_without_retrieval`，通过既有`PROVIDER_INVALID_RESPONSE`失败链路保存；已检索时继续执行原来源与分区校验。格式修复也携带当前状态，仍不能改正文事实、编造引用或执行工具。
- [ToolActivity.vue](../frontend/src/components/ToolActivity.vue)与[runEventReducer.ts](../frontend/src/events/runEventReducer.ts)：原有正式实现已经只依据真实工具事件展示过程，本包补回归验证，不从模型正文推导工具执行状态。

## 回答形式与失败语义

| 实际情况 | 格式与行为 |
| --- | --- |
| 尚未检索，直接回答普通问题 | 普通正文，不要求两个分区；不能声称查过或输出文档引用 |
| 实际检索，有足够依据 | 文档依据分区，每段引用本 Run 实际证据；模型补充按需要另列 |
| 实际检索，但候选不足以支持问题 | 明确不足；无可用文档依据时使用补充分区，不强造文档分区 |
| 健康检索为空 | 根据工具结果区分无已发布文档、无命中等情况 |
| 检索或Provider失败 | 原typed error与失败终态，不转换为空检索结果，不让模型继续编写“未找到” |

普通无工具回答仍按原协议流式提交。因此违规标记可能先作为临时/未完成文字到达浏览器，最终校验会将该Run标为失败；不删除已提交的半截正文、不伪造成功或有效引用。工具模式仍整轮缓冲。自由文本中的任意“我查过”无法靠正则完全识别，系统规则减少该表述，界面过程以事件为准；当前引用校验证明来源存在，不等于证明每项事实在语义上得到支持。

历史失败或无来源回答不原地重写，也不补造来源。重启API后，可在原Thread发送新问题应用新规则，无需因本修复重传文档或重建向量。
