## 开章计划

计划日期：2026-11-18。

### 目标与参考范围

将MiniMew从当前“账户首页＋顶部并列导航＋分散的项目/对话页面”，整理成以对话为中心的浏览器工作区。用户提供的deepseek_harness截图仅作为布局与信息层级参考：左侧持续可见的工作区/会话导航，右侧新会话或当前对话主区域；不复制其品牌、桌面窗口、插件、自动化任务、附件或尚未实现的模式。

用户已确认：登录后进入新会话页；发送首条消息时才创建Thread；左侧个人空间与项目可展开各自会话；点击项目名称展开会话，项目概览/设置另设入口；“文档”和“评测”保留一级入口；文档入口跟随当前个人或项目工作区，并明确显示所属范围。

### 模块关系与状态归属

计划中的UI数据流：认证恢复 → 工作区选择（个人或项目）→ 左栏加载该范围的会话 → 新会话输入或打开既有Thread → 原Thread/Run API与Chat Store → 原Event Journal/SSE投影。工作区选择是浏览器导航上下文，不替代服务端对Project、Thread、Document的归属检查。项目记忆仍由项目页面/服务端保存；Run/Message/Event及终态仍由后端负责。

首次发送需利用现有创建Thread和提交Run入口，实施时核对创建结果不确定、重复点击、切换工作区和提交失败的处理。UI不能凭本地发送状态宣布Run完成。文档页沿用现有个人/项目过滤；评测保持现有全局工作台语义，不因当前项目改变评测数据范围。

### 视觉与验证边界

优先复现参考图的空间组织、侧栏层级、中心输入区和安静的阅读节奏；具体字色、字号与组件形态以MiniMew内容和可访问性为准，不做逐像素复制。已有技术栈Vue 3、Pinia、Vue Router、Vitest、Playwright继续使用；本计划未选定新增依赖。

实施后按受影响范围验证路由、工作区隔离、首发创建/提交、现有聊天恢复与文档归属；实际页面流程用浏览器检查桌面和移动宽度。没有行为变化的后端和评测不因界面重排而机械全量复验。

## 结章总结与实际代码框架

总结日期与实际覆盖范围：2026-11-20，于基于 `43e029b4` 展开的独立 worktree 分支 `feat/minimew-ch10-ui` 完成 10.1–10.4 前端工作区架构与交互重构。并行开发期间只改动 `MiniMew/frontend/` 与本章文档，不改动后端代码、数据库迁移、OpenAPI/Event 契约及共同交接文档，以便后续无痛合并回主分支。

### 本章实现了什么

1. **10.1 应用工作区外壳**：
   - 登录后及默认根路径 `/` 统一进入新会话页 `/threads`；直接打开或刷新 `/account`、`/documents`、`/projects/:id`、`/evaluations`、`/threads/:id` 仍准确恢复到原页面。
   - 已登录态采用左侧常驻工作区导航（`WorkspaceSidebar.vue`）+ 右侧主区域的布局；未登录、恢复中与连接错误态保持原有居中壳层（`.shell`）。
   - 窄屏（`<= 900px`）自动切换为顶栏 + 滑出式侧栏抽屉，支持遮罩点击与 `Esc` 关闭，移动端无横向溢出。
2. **10.2 项目与会话层级**：
   - 新增分桶工作区导航状态 `useWorkspaceStore`，将个人空间（`personal`）与各个项目（`projectId`）的会话列表、分页游标、加载态与错误态完全隔离，互不串列表、不串选中态。
   - 左侧点击项目名称展开/收起该项目会话并切换当前工作区上下文；每个项目旁保留独立的“概览”入口进入 `/projects/:projectId` 管理项目记忆与概览；离开项目页不再清空左栏项目目录。
3. **10.3 新会话与首发创建**：
   - 新增 `NewChatPanel.vue` 与 `useNewChatStore`，`/threads`（个人）与 `/threads?project=<id>`（项目）呈现居中的新会话输入区与任务模式（Skill）选择器。
   - 空白草稿禁用发送、不调用 `POST /v1/threads`。
   - 首发发送分两阶段：阶段 A 调用 `POST /v1/threads`（按当前 scope 传 `{}` 或 `{ project_id }`），失败时保留本地草稿与提示且不自动重试；阶段 A 成功后立即将 Run 意图（含原 `idempotency_key`、正文与 Skill）写入 `minimew.chat-pending:<userId>:<threadId>` 再执行阶段 B `POST /v1/threads/:id/runs`。无论阶段 B 成功或失败都导航到目标 Thread，失败时由 `ChatPanel` 直接恢复“重试原提交”，绝不重复创建 Thread 或 Run。
4. **10.4 文档、评测与整体体验**：
   - 左侧一级入口“文档”自动跟随当前工作区（个人或项目）并显示范围徽章；`DocumentsView.vue` 顶部明确标明“个人知识库”或“项目知识库 · <项目名>”，并支持从项目文档快捷切回个人文档，保留 `KnowledgeEmbedding.vue` 全部重建与下线能力。
   - 左侧一级入口“评测”固定指向 `/evaluations` 并标注“全局”，不随左侧项目切换业务范围。
   - 账户与模型设置（`AccountModels.vue`）、Skill 选择、HITL、引用、执行过程均作为独立能力块完整保留在新工作区中。
5. **全站视觉与组件布局重做（白色 + 淡蓝体系）**：
   - 彻底移除旧青绿色系，建立统一 CSS 变量体系（纯白主画布 `#ffffff`、冷雾侧栏 `#f7f9fc`、淡蓝高亮 `#e8f1ff` / `#f0f6ff`、主蓝 `#2563eb`、石板灰字阶 `#0f172a` / `#334155` / `#64748b`），同步覆盖全局 `style.css` 及全部 10 个带 `<style scoped>` 的视图与子组件。
   - 收敛字号与控件比例：正文 `14px`（聊天阅读 `15px`）、常规按钮 `36px`（紧凑按钮 `26–30px`）、页标题 `20–24px`，消除原 `48px` 笨重按钮与超大标题。
   - 对话页改为全高 Flex 布局（顶部 `56px` 固定栏 + 中部占满视口的可滚动居中消息流 + 底部固定统一圆角输入卡 `.composer-card`，任务模式选择器与发送按钮内嵌在同一输入卡底栏），取代原 `58vh` 截断式消息区和堆叠表单。

### 关键概念与取舍

- **工作区上下文是浏览器导航态，不替代服务端授权**：`useWorkspaceStore.activeScope` 只决定左侧展开态、新会话归属与“文档”入口链接；所有 Thread、Project、Document、Run 的权限与归属仍由后端校验。
- **保留 `useThreadsStore` 既有接口**：不重写既有 `threads.ts` 契约，新增 `workspace.ts` 负责侧栏多桶会话列表，新增 `newChat.ts` 负责首发两阶段创建与草稿转交，保持 `stores/chat.ts` 与既有单测零回归。
- **阶段 A → 阶段 B 意图转交**：利用 `chat.ts` 已验证的 `minimew.chat-pending:<userId>:<threadId>` 幂等恢复键，把新会话阶段 B 失败后的恢复统一收口到目标对话页，避免在两个页面维护两套 Run 重试逻辑。

### 代表性流程走读（项目新会话首发发送）

1. 用户登录或刷新进入 `/threads` → `App.vue` 渲染 `WorkspaceSidebar` + `ThreadsView`。
2. 用户在左栏点击项目名称 → `workspace.toggleScope(projectId)` 展开该项目桶并加载 `/v1/threads?project_id=<id>`，一级入口“文档”与“新会话”按钮随之切换到该项目上下文。
3. 用户点击“＋ 本项目新会话”进入 `/threads?project=<id>` → `ThreadsView` 渲染 `NewChatPanel`，`newChat.openScope(projectId)` 恢复可能存在的未确认草稿并加载 `/v1/skills`。
4. 用户输入问题并发送 → `newChat.submitFirstMessage()` 先 `POST /v1/threads`（带 `project_id`）→ 成功后写入 `workspace.upsertThread` 并将 Run 意图转存到 `minimew.chat-pending:<userId>:<threadId>` → 再 `POST /v1/threads/:id/runs`（带 `idempotency_key`、正文、Skill）→ 导航到 `/threads/:id?project=<id>`。
5. `ThreadsView` 挂载 `ChatPanel` → 若阶段 B 已成功则自动加载历史并接入 SSE 流；若阶段 B 失败则直接恢复 `chat-pending` 草稿，点击“重试原提交”沿原 `idempotency_key` 重发 Run，不重复创建 Thread。
