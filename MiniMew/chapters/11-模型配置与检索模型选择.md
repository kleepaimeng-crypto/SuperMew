### 本章目标与已有基础

在账户设置中选择聊天模型配置，并可填写其他开发商模型所需信息；账户未设置模型时沿用本机 `.env` 对应的默认配置。Embedding 与 Rerank 各自支持选择本地模型或 API。选择应能追溯到实际 Run、文档构建和检索执行，不把页面选择误当作已切换的索引或已验证的模型能力。

当前已有 `model_control.py` 的 answer Profile/Run 冻结；`model_protocol.py` 目前只接受 `openai_compatible`，实际 Provider 另有端点与凭据限制。`documents/profiles.py` 只定义两个固定本地 Embedding 预设，构建配置有 fingerprint；`knowledge_runtime.py` 在 API 启动时加载固定本地编码器和本地 Base Reranker。第九章9.5已规划模型控制面，本章负责把用户新增的聊天/Embedding/Rerank 来源选择及其端到端语义讲清；实施时应调整9.5职责，避免两个配置页面或两套事实来源。

### 学习节奏与工作包

先走读“账户设置 → 服务端解析配置 → Run/构建快照 → Provider 或本地 Adapter → 结果与错误”，重点讲聊天生成、Embedding 向量空间、Rerank 排序的不同职责及切换影响。常规表单/API/持久化可集中开发；索引版本、凭据边界、Provider 兼容、冻结与评测可比性是本章的关键架构决策。11.1–11.4可按依赖分为聊天模型配置包、检索模型来源包，具体范围在编码前列明并取得开始反馈，包内连续实施和集中验收。

沿用 Python/Pydantic、PostgreSQL/Alembic、Vue/Pinia、既有 Provider/Embedding/RAG 接口与 Run/Document Version 生命周期。是否需新增 SDK、依赖或 API 适配器，要在具体 Provider 协议与能力确定后核对，不预设所有开发商都兼容同一种接口。

### 数据流与关键边界

```text
聊天：读取当前账户的模型设置；未设置则使用服务端 .env 默认
      → 服务端校验与取密钥 → 新 Run 冻结无密钥快照
      → 原执行器/Provider → 原 Event Journal、Message 与终态

入库：Embedding 配置 → 冻结 BuildConfiguration → Index Worker 编码
      → candidate 索引/manifest 核验 → 原子发布 Document Version

查询：已发布索引的 Embedding 身份 → 同身份查询编码 → Dense/Hybrid 候选
      → 冻结的 Rerank 来源执行 → Evidence/原答案链
```

- `.env` 是默认来源，不应从浏览器读取或把其中密钥回显。其他开发商的凭据保存、轮换、访问权限与运行时读取方式在编码前确定；原始密钥不进入公开响应、Run/Checkpoint/Event、文档构建快照或评测报告。
- 聊天模型选择是账户级设置，优先于服务端 `.env` 默认；账户没有设置时才使用 `.env`。切换只影响之后创建的 Run；旧 Run、HITL 恢复和幂等重试继续使用原模型快照。清除账户设置后，新 Run 重新使用 `.env` 默认。
- Embedding 改变可能改变向量维度、归一化、前缀或语义空间。个人库和各项目库分别选择，切换时按选定库构建并核验候选索引集合。发布后查询使用与新集合匹配的编码器，旧版本与历史引用保持可追踪。
- Rerank 在原 Pipeline 内执行，不能产生第二条知识问答路径。保持固定候选范围、预算、截止时间、一次重试所有者与可审计失败/允许降级；服务端限制 API 目标和凭据用途，不能让用户配置变成任意内网 URL 访问。
- Evaluation Job 的模型、语料、索引与策略来源需冻结并写入可比 provenance；来源变化后不能直接与旧 baseline 宣称质量提升。真实 API 调用、下载模型或重建用户索引要等相应工作包明确范围。

聊天模型 Provider 和凭据方案已随 11.1 落地。Embedding 首版选择见下节，Rerank 的来源和生效范围在 11.3 单独讨论。

## 11.2 Embedding 切换工作包讨论（2026-11-20）

11.1 账户模型设置已交付。用户明确选择“个人知识库和各项目知识库独立设置”。11.2 以知识库为 Embedding 生效与重建单位：个人知识库和每个项目分别保存当前已发布配置与候选目标；重建只处理被选知识库中的文档。账户页可以继续承担模型配置入口，具体生效状态由对应知识库持有。Rerank 留 11.3，作用域另行确认。

| 顺序 | 模块与职责 | 验收 |
| --- | --- | --- |
| A | 统一 Embedding 编码接口，接现有本地实现和一个确认协议的 API 实现。BuildConfiguration 冻结模型身份、维度和编码参数，私有凭据按授权读取 | 受控 API 与现有本地路径均能构建与查询；向量身份和维度匹配；凭据不进入公开快照 |
| B | 设置候选构建目标，在现有 Index Job 和 Worker 上为目标知识库重建索引，核验后整体切换查询可见的已发布索引集合 | 构建中继续查旧索引，失败继续使用旧索引；并发上传、下线和历史引用纳入切换验证 |
| C | 查询读取已发布的索引集合并使用匹配的编码器；界面展示当前模型、目标模型、重建进度及失败 | 切换前后查询均匹配对应索引；旧执行保有必要的读取窗口；重建失败可定位并重试 |

现有源码入口是 `documents/profiles.py` 的 BuildConfiguration、`documents/worker.py` 的文档编码与发布、`documents/retrieval.py` 的 published_scope、`rag/pipeline.py` 的查询编码以及 `knowledge_runtime.py` 的本地实现装配。技术上沿用 PostgreSQL/Alembic、Milvus、现有 Worker 和 RAG Pipeline，新增的是 Embedding API 适配器和整库索引集合的切换能力。API 方案会将对应知识库的文档分块与查询词发给指定服务商，重建应由用户显式触发。

用户明确选择“先做百炼预设”。首版保留现有本地模型，并增加 `text-embedding-v4` 固定预设，使用[阿里云百炼的 OpenAI 兼容 Embedding 接口](https://help.aliyun.com/zh/model-studio/embedding-interfaces-compatible-with-openai)。模型 ID、向量维度和服务端点由预设管理，API Key 走账户的加密凭据机制。通用 Base URL 和自定义模型留待后续。

用户为指定知识库选择目标并发起重建后，系统冻结候选参数与凭据引用，Worker 按该库的已发布文档构建候选索引。发布事务核验文档集合和候选结果，统一切换索引集合及其 Embedding 身份。验收覆盖库间隔离、切换失败时原索引可用、重试与历史引用，API 侧用受控响应。用户已回复「开始 11.2」，实施范围如下。

## 11.2 实现与代码框架

```text
个人或项目文档页 → 所有者校验 → 目标配置和持久重建任务
  → 原 Index Worker → 冻结源版本 → 分块 → 本地或百炼编码
  → Milvus 候选范围及清单核验 → 各文档等待整库发布
  → PostgreSQL 同一事务切换有效文档 current 与知识库构建方式

问答 → 已发布 scope → 匹配的查询编码器 → 原 Dense / Hybrid RAG → Evidence / 引用
```

| 源码入口 | 职责 |
| --- | --- |
| `api/documents.py`、`documents/rebuilds.py` | 读取当前配置，校验项目归属，接收显式重建，登记旧版本与候选任务，按库汇总进度和发布 |
| `documents/jobs.py`、`documents/worker.py` | 复用 Index Job 的短事务、lease、fence 和精确核验。已核验子任务进入 `ready` 等待整库发布，Worker 重启后仍可汇合 |
| `embeddings/bailian.py`、`documents/profiles.py` | 固定百炼 `text-embedding-v4`、512 维和中国内地端点。沿用本地分块预算，验证 API 返回索引、模型、维度和向量，统一归一化。凭据随构建冻结，密文与原始 Key 均不进入公开视图 |
| `vector_store/manifest.py`、`vector_store/milvus.py` | 512 维的本地和百炼仍属不同向量空间，使用独立集合，并保留原 Dense/BM25 布局与历史产物身份 |
| `documents/retrieval.py`、`rag/pipeline.py` | 一次目录快照取得当前版本、产物和私有凭据引用，产生与已发布空间匹配的查询向量。已读取固定范围的执行按原保留窗口完成 |
| `frontend/src/components/KnowledgeEmbedding.vue` | 个人和项目分别展示当前模型、目标、已核验进度与失败。切换动作位于对应文档页 |

重建前需要等该库旧构建结束。重建期间，同一库的新上传和新版本明确等待，查询及下线可继续，其他库独立操作。失败时撤销未发布候选，重试重新登记候选。历史 Document Version 和引用保留。当前仅接入本地 BGE Small 与百炼固定预设，百炼 Key 按账户加密并绑定知识库。API Embedding 的独立评测语料绑定留在 11.4，现有本地评测继续复用原链路。

迁移 `0024` 新增重建记录、库凭据引用、子任务归属及核验就绪约束。旧配置、发布指针和 Milvus 集合命名沿用旧值。部署时配套升级 API、Index Worker 和前端。

## 11.3 Rerank 来源切换工作包讨论

当前 `rag/pipeline.py` 先执行 Dense、BM25、RRF 和同节补全，再按冻结的 `RagPolicy` 调用 `knowledge_runtime.py` 装配的本地 BGE Reranker Base，最后选取 Evidence。现有纯 Dense 路径不进入重排步骤。Embedding 决定召回空间，Rerank 给已召回候选打分，因此切换 Rerank 可以在下一次 Run 生效，无需重建索引。

| 顺序 | 建议范围 | 验收 |
| --- | --- | --- |
| A | 保留本地 BGE Base，建议接[百炼 `qwen3-rerank` 预设](https://help.aliyun.com/zh/model-studio/text-rerank-api)。统一原候选评分接口，按返回的索引映射候选分数 | 同批候选通过两种适配器可排序，拒绝缺项、重复索引或无效分数，原分组、引用和有界候选数保持 |
| B | 读取设置并在 Run 创建事务冻结来源和私有凭据引用，原执行器和 HITL 恢复沿同一选择 | 改设置后新 Run 生效，重试与等待恢复使用原选择。历史本地快照保持可读 |
| C | 复用现有重排降级与过程事件，显示所选模型和降级原因。控制面按确认的作用域展示 | API 故障且仍有执行时间时使用 RRF 原排序，耗尽期限时依现有语义终止。受控 API 验证成功、失败与恢复 |

用户明确选择「Rerank 也按个人库和各项目库独立设置」。在对应文档页的知识库设置中分别选择 Embedding 和 Rerank。例如项目 A 可用本地 Embedding 搭配百炼重排，项目 B 两项都用本地。保存 Rerank 即可供新 Run 读取，沿用已发布的文档索引。

首版建议未设置时沿用本地 BGE Reranker Base，另提供百炼 `qwen3-rerank`。启用百炼时在该库填写 Rerank 的 API Key，复用账户加密凭据机制。将重排凭据与 Embedding 凭据独立引用，使用户可为任一能力单独启用百炼。百炼重排接收本次检索词与进入重排的候选片段。

`conversations.py` 的 `reserve_run` 已在事务中冻结模型和现有 RAG 策略。11.3 在同一事务按 Thread 的知识库归属冻结重排来源及私有凭据引用，执行器继续通过原策略把选择交给 `rag/pipeline.py`。验收增加跨库隔离、设置切换前后 Run 的一致性和受控 API 降级。真实费用调用、通用 API 和评测模型绑定留待后续。用户已回复「开始 11.3」。

## 11.3 实现与代码框架

```text
文档页重排设置 → 个人库或项目库 → 版本化加密凭据
  → reserve_run 冻结来源与私有凭据引用 → 原 RunExecutor / HITL
  → Dense + BM25 → RRF → 同节补全 → 本地 BGE 或百炼 qwen3-rerank
  → 证据选择、引用与原过程 Journal
```

| 模块 | 职责 |
| --- | --- |
| `api/documents.py`、`documents/rerank_settings.py` | 读写知识库自己的重排设置。项目归属使用原校验，凭据版本绑定账户和百炼固定端点，公开视图只显示已配置与否 |
| `conversations.py`、`execution/repository.py` | 原创建事务冻结 `RagPolicy` 与私有凭据引用。交给原执行器，重试或恢复时从持久 Run 读取。旧快照的本地策略字段和摘要不变 |
| `rag/pipeline.py`、`rag/bailian_reranker.py` | 共用原候选、排序和 Evidence 路径。百炼响应按候选索引校验并回填，API 故障可显式沿用 RRF，期限耗尽终止 |
| `frontend/src/components/KnowledgeRerank.vue`、`ProcessTask.vue` | 在文档页切换来源，在原检索详情展示使用的模型和降级原因 |

迁移 `0025` 为知识库保存选择，为 Run 保存不可改写的私有凭据引用。切回本地时保留这个库已保存的重排凭据，轮换新 Key 后已创建的 Run 继续使用原凭据引用。百炼调用不依赖本地重排模型就绪。本地重排模型缺失时使用既有 RRF 降级并记录原因。Embedding 建库及索引发布链仍独立工作。受控评测继续要求本地重排，API 重排的评测绑定留到 11.4。
